# 린 가상 고객 인터뷰

## 목적

가상 고객 인터뷰를 **실제 인터뷰 전 리허설**로 쓴다. 이 스킬로 다음을 얻는다.

- 유도 질문과 미래 가정 질문이 걸러진 인터뷰 스크립트
- 페르소나별 인터뷰 기록과 요약 (Validates / Invalidates / Also Interesting / 감정)
- 세그먼트 간 패턴과 새로 생긴 가설 후보
- **실제 고객 인터뷰 계획**: 모집 기준, 스크리너 질문, 수정된 스크립트, 종료 기준

가상 고객의 답은 합성 데이터에서 추론한 것이다. 문제를 검증했다는 판정은 실제 사람에게서 행동 증거(시간, 돈, 노력을 들인 흔적)를 확인한 뒤에만 내린다. 이 스킬의 결론은 "가설 후보"와 "실제 인터뷰에서 확인할 것"으로 표기한다.

## 모드

| 모드 | 언제 | 인터뷰어 | 가상 고객 |
|---|---|---|---|
| **A. 시뮬레이션** (기본) | 스크립트를 빠르게 돌려 보고 가설 후보를 얻을 때 | Claude | 페르소나별 서브에이전트 (가설 모름) |
| **B. 연습** | 사용자가 인터뷰 기술을 연습할 때 | 사용자 | Claude가 카드 1장을 연기하고, 끝나면 코칭 |
| **C. 스크립트 점검** | 질문지만 검토할 때 | — | — |

## 입력

| 입력 | 없을 때 |
|---|---|
| 문제 가설 ("[누가] [무엇을 할 때] [어떤 문제]를 겪는다") | 사용자에게 묻는다 |
| 인터뷰 종류 | 문제를 아직 찾는 중이면 문제 인터뷰, 문제가 확인됐고 해결책·가격을 보려면 솔루션 인터뷰 |
| 종료 기준 | 기본값 제안: "5명 중 2명 이상이 최근 3개월 안에 이 문제로 돈·시간·도구를 써 본 적이 있다" |
| 페르소나 카드 | 없으면 `korean-customer-persona` 스킬로 먼저 만든다 (5~8명 + 경계 사례 1~2명) |
| 산출물 폴더 | 기본값 `interviews/<프로젝트-슬러그>/<YYYY-MM-DD>/` |

## 절차 (모드 A)

### 1단계. 가설과 종료 기준을 먼저 적기

인터뷰를 시작하기 전에 `00-plan.md`에 다음을 쓴다: 문제 가설, 가장 위험한 가정 1~3개, 종료 기준, 인터뷰 대상 표. 결과를 보고 나서 기준을 바꾸지 않도록 하기 위해서다.

### 2단계. 스크립트 작성

`references/interview-scripts.md`의 문제 인터뷰 또는 솔루션 인터뷰 뼈대를 주제에 맞게 채운다. 문제 인터뷰의 중심은 **가장 최근의 구체적 사건**을 시간순으로 재구성하는 것이다(계기 → 탐색 → 선택 → 사용 → 지금). 완성한 스크립트는 `references/question-checklist.md`로 한 문항씩 점검하고, 걸린 문항은 고쳐서 `00-script.md`에 저장한다.

### 3단계. 가상 고객 에이전트 띄우기

페르소나마다 독립된 서브에이전트를 하나씩 둔다. 같은 에이전트에게 여러 사람을 연기시키지 않는다.

- 에이전트 타입: 플러그인으로 설치했으면 `virtual-customer`, 아니면 `general-purpose`에 `references/virtual-customer-prompt.md` 전문을 넣는다.
- 넘기는 것: 연기 지침 + 페르소나 카드(A~C 섹션) + 인터뷰 상황 한 줄("평일 저녁 생활 방식에 대해 30분 정도 이야기 나누기로 한 연구 인터뷰"). 카드는 인터뷰어 메타데이터를 지운 블라인드 사본을 작업 폴더 밖(임시 폴더)에 만들어 경로로 넘기면 된다: `grep -v -E '^(segment_role|project):' card.md > /tmp/.../blind/card.md`. 에이전트에게는 "지침 파일과 카드 파일만 읽어라"라고 명시한다.
- **넘기지 않는 것**: 문제 가설, 제품 아이디어, 회사 이름, 인터뷰 목적, 다른 페르소나.
- 서로 독립적이므로 모든 페르소나의 첫 라운드를 한 메시지에서 병렬로 띄운다.

### 4단계. 라운드제 인터뷰 진행

한 라운드에서 스크립트 블록 하나(질문 2~4개)를 보낸다. 답을 읽고 다음 라운드의 후속 질문을 만든 뒤, `SendMessage`로 같은 에이전트에게 이어서 묻는다. `SendMessage`를 쓸 수 없는 환경이면 지금까지의 대화 기록 전체를 새 에이전트에게 넘긴다.

- 라운드 1: 오프닝과 일상 맥락
- 라운드 2: 가장 최근 사건의 시간순 재구성 (계기, 그 전후)
- 라운드 3: 지금 쓰는 방법, 들인 돈·시간, 불만, 바꿔 본 경험
- 라운드 4: 후속 질문 (답이 막연한 곳, 감정이 드러난 곳, 예상과 다른 곳)
- 라운드 5: 마무리 (더 물어봤어야 할 것, 소개해 줄 만한 사람)
- 빠르게 돌릴 때는 3라운드로 줄인다: ① 맥락 ② 최근 사건 재구성 ③ 요약 확인 + 기존 대안·비용 + 마무리. 라운드 2 이후부터는 페르소나마다 답에 맞춘 후속 질문을 넣는다. 스크립트를 그대로 복사해 보내지 않는다.
- (솔루션 인터뷰) 라운드 4 이후에 데모 설명 → 첫 반응 → 가격 제시 → 다음 행동 요청 순서로 진행

인터뷰어 규칙은 다음과 같다.
- 제품을 설명하거나 가설을 말하지 않는다. "문제"라는 단어를 쓰지 않는다.
- 막연한 답("자주요", "불편하죠")에는 반드시 한 번 더 묻는다: "마지막으로 그랬던 게 언제예요?", "그때 어떻게 하셨어요?"
- 들은 내용을 요약해 되묻고 틀린 곳을 고쳐 달라고 한다.
- 미래 가정 질문("쓰실 건가요?", "얼마면 사실래요?")은 하지 않는다.

각 인터뷰 기록은 `<번호>-<이름>.md`에 질의응답 원문 그대로 저장한다.

### 5단계. 인터뷰별 정리

`references/synthesis-template.md`의 인터뷰별 양식으로 기록 바로 아래에 붙인다.
- Validates / Invalidates / Also Interesting / 감정 신호 (각 1~3줄, 원문 인용 포함)
- 증거 등급: 과거 행동(돈·시간·도구 사용) > 구체적 일화 > 일반론·의견 > 미래 의향. "아마도"는 "아니오"로 기록한다.
- 문제 강도: 반드시 필요 / 있으면 좋음 / 필요 없음
- 고객 작용력: 밀어내는 힘(현재 불만), 끌어당기는 힘(바라는 상태), 관성(익숙함), 마찰(바꾸기 어려운 이유)

### 6단계. 종합과 다음 행동

`99-synthesis.md`를 쓰고 사용자에게 요약을 보고한다.
1. 패턴 표: 페르소나 × 주요 발견 (3명 이상에게서 나온 것만 "패턴")
2. 경계 사례와 비교: 패턴이 경계 사례에서도 나오면 세그먼트 정의가 핵심을 잘못 짚은 것
3. 종료 기준 대비 결과: "가상 인터뷰 기준 충족 / 미충족" (검증 아님)
4. 가설 수정안: 더 좁힌 세그먼트, 바뀐 문제 정의, 새로 생긴 위험한 가정
5. **실제 인터뷰 계획**: 모집 조건(가상 인터뷰에서 반응이 강했던 페르소나의 공통 행동 기준), 스크리너 질문 3~5개, 고친 스크립트, 실제 인터뷰 종료 기준
6. 가상 인터뷰의 맹점: 합성 데이터에 없는 정보(소득, 실제 앱 사용 이력)에 기댄 결론이 어느 것인지. 모든 에이전트가 같은 모델이므로 "전원 일치" 패턴은 모델 공통 편향일 수 있다. 그 패턴이 카드 B에 직접 쓴 내용에서 나왔는지, 에이전트가 스스로 만든 것인지 구분해 적고, 실제 인터뷰에서 가장 먼저 확인할 항목으로 올린다.

## 절차 (모드 B: 연습)

1. 사용자에게 페르소나 카드 1장을 고르게 하고, Claude가 `references/virtual-customer-prompt.md` 지침대로 그 사람이 된다.
2. 사용자가 질문하면 Claude는 인물로만 답한다. 사용자가 "타임아웃" 또는 "피드백"이라고 하면 역할에서 나와 지금까지 질문을 코칭한다.
3. 종료 시 `references/question-checklist.md` 기준으로 질문별 피드백 표를 준다(유도 질문, 미래 가정, 피칭, 놓친 후속 질문, 좋았던 질문). 각 문제 문항에는 고쳐 쓴 예시를 붙인다.

## 절차 (모드 C: 스크립트 점검)

질문지를 받아 `references/question-checklist.md`로 문항별 통과/수정을 표로 돌려주고, 고친 전체 스크립트를 제시한다.

## 예시

`examples/dual-income-childcare/`(저장소 루트)에 전체 실행 결과가 있다. 세그먼트 집계, 후보 풀, 페르소나 카드 5장, 계획·스크립트, 인터뷰 5건 원문과 요약, 종합이 들어 있다.
