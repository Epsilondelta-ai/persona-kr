# 질문 점검표

질문 하나마다 아래 7개를 확인한다. 하나라도 걸리면 고친다.

| # | 기준 | 걸리는 예 |
|---|---|---|
| 1 | 미래가 아니라 **과거 행동**을 묻는가 | "앞으로 이런 앱을 쓰실 건가요?" |
| 2 | 일반론이 아니라 **특정한 한 번**을 묻는가 | "보통 어떻게 하세요?" (맥락 질문 1번 외에는 피한다) |
| 3 | **열린 질문**인가 (예/아니오로 끝나지 않는가) | "불편하신 적 있으세요?" |
| 4 | 답을 **유도하지 않는가** | "그게 제일 힘드시죠?" |
| 5 | 내 **아이디어나 제품을 노출하지 않는가** | "AI가 대신 해 주면 어떨까요?" |
| 6 | 검색하면 알 수 있는 걸 묻지 않는가 | "요즘 어린이집 하원 시간이 몇 시예요?" |
| 7 | 의견·평가보다 **과정과 행동**을 묻는가 | "이 서비스 괜찮다고 보세요?" |

## 나쁜 질문 → 좋은 질문

| 나쁜 질문 | 왜 문제인가 | 고친 질문 |
|---|---|---|
| 이런 서비스가 있으면 쓰시겠어요? | 미래 의향은 예의상 "네"가 나온다 | 지난번에 이 일 때문에 뭔가를 찾아보거나 결제해 보신 적 있어요? 그때 얘기 해 주세요. |
| 한 달에 얼마까지 내실 수 있어요? | 사람은 지불 의사를 예측하지 못한다 | 지금 이 일에 지난달 실제로 쓴 돈이 얼마쯤이에요? 어디에 썼어요? |
| 하원 시간 맞추기 정말 힘드시죠? | 답을 정해 놓은 유도 질문 | 지난주 하원은 어떻게 하셨어요? 누가 데리러 갔어요? |
| 얼마나 자주 그런 일이 있어요? | 평균을 물으면 부풀려진다 | 지난 한 달 동안 그런 날이 몇 번 있었어요? 가장 최근은 언제였어요? |
| 가장 큰 불편이 뭐예요? | 즉석에서 지어낸 순위가 나온다 | 최근에 "아 이건 진짜 어떻게든 해야겠다" 싶었던 순간이 있었어요? |
| 저희가 만드는 앱은 ○○ 기능이 있는데요… | 피칭이 시작되면 상대는 예의를 차린다 | (문제 인터뷰에서는 제품 설명 금지. 질문받으면 "먼저 ○○님 얘기를 듣고 끝에 말씀드릴게요") |

## 답변 해석표

| 들은 말 | 해석 |
|---|---|
| "좋네요", "쓸 것 같아요", "있으면 편하겠다" | 증거 아님. 칭찬으로만 기록 |
| "아마", "글쎄요", "생각해 볼게요" | "아니오"로 기록 |
| "보통은", "항상", "절대" | 일반론. 특정 사례로 다시 묻는다 |
| "지난달에 ○○ 써 봤다가 ○○ 때문에 그만뒀어요" | 강한 증거 (시도 + 이탈 이유) |
| "그래서 엑셀로 따로 정리해요", "친정엄마한테 부탁해요" | 강한 증거 (스스로 만든 대안 = 해결할 가치) |
| "불편하긴 한데 뭐 다들 그렇게 살죠" | 문제는 있지만 강도 낮음. 해결 시도 여부를 확인 |
| 묻지 않았는데 먼저 꺼낸 불만 | 묻고 나서 나온 동의보다 무겁게 본다 |

## 인터뷰 후 자가 점검 (2명마다)

1. 이 사람에게 문제를 완벽히 해결하는 제품이 오늘 있다면, 쓰는 데 걸림돌은 무엇인가?
2. 하루 중 언제, 어떻게 쓰게 되는가?
3. 그 제품은 지금의 무엇을 대체하는가?
4. 쓰지 않는다면 정확히 왜인가?

네 가지에 답할 수 없으면 질문을 바꾼다.
